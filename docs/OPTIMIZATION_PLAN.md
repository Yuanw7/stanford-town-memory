# Memory 优化实施计划

2026-10-14，根据 MISSION、当前源码和已保存的阶段证据制定。本文是下一步实施任务与判定规则，不代表策略已经实现或收益已经验证。阶段总路线仍以 ROADMAP 为准。

## 使命确认与证据边界

目标是在相同任务、相同观察资格和可接受质量下，减少上下文及总运行消耗，并暴露长期运行的失败条件。优化结果可以是无收益，不以缩短 prompt 本身作为成功。

| --- | --- |
| P2 连续 30 分钟新增 19 段对话、36 条记忆；317 次请求成功结束 | 已有工程环境；不用反复跑相同启动验收来代替策略研究 |
| 全历史诊断：100 条准确率 100%，1000 条 96% | 只证明这些任务的诊断能力；完整原版记忆基线仍缺失 |
| 1000 条长历史在 4K 输入预算下被拒绝，调用为 0 | 说明该全历史配置不可执行；不能推断所有 4K 检索方案都差 |
| 当前 100/1000 是全镇总观察量，各角色为 20/200 条 | 每个报告同时列全镇观察数、每角色可见数、写入后记忆数；不同量不混用 |
| 现有候选重排与预算模块已实现 | 它没有真实写入、摘要、importance、反思流程，不能命名为完整 baseline |

## 优化假设与顺序

第一优先验证预算检索：保留原版写入、评分、反思、embedding 和候选数量，只改变选择规则。预计维护开销最少；主要风险是长条被跳过后关键证据缺失，或预算根本不生效。比较前记录候选、分数、每条 token、实际选择和排除原因。

第二优先验证分层记忆：保留不可变原始事件，将近期情节、有效事实、待履行承诺和归档分开。主要假设是减少反复读取冗余历史；主要风险是维护调用昂贵，以及摘要丢掉时间、否定、人物或更新关系。先实现来源追溯和事实版本，再增加生成式压缩。

上下文不足时有可观察的处理：核心任务模板已溢出则拒绝；检索条目过长则整条跳过并记录；分层策略找不到必要证据时可按已冻结配置查归档，查询与维护开销全部入账。禁止静默截断。增加窗口、换模型、修改 K 或调度作为后续独立变量。

## A：固定实验契约与补齐计量

交付：开发数据清单、模型/源码快照、提示词版本、逻辑时钟、质量指标定义、反思路径独立探针。

- 维持 town-qwen、当前 embedding digest、并发 1、8K 主窗口；4K 作为后续压力对照。每次运行在发送调用前核查服务和配额。
- 将 observation、conversation、memory 三种数量区分。v2 输入显式携带会话边界、作者、参与者、观察资格、时间与事件 ID；不由标准答案倒推写入内容。
- 当前合成单条 observation 没有完整会话结构，不可直接套上原版会话摘要标签。保留 v1 用作诊断，为真实会话写入另建 v2 并保留转换来源。
- 各组使用同一显式逻辑时间序列，维护 recency 不依赖哪组运行更慢。在线仍记录墙钟与模拟时间，不能混写。
- 用独立受控记忆 fixture 触发原版反思条件，验证 reflection、reflection_importance、reflection_embedding 的归属、终态和 usage。探针与小镇生产证据分开，不降低正常阈值冒充自然触发。
- 当前题集已经多次用于诊断；策略调试只用开发集。正式策略验收另冻结独立留出数据并人工核验，保留原题集和结果。重复运行不增加独立问题数量。

完成条件：输入与答案分离；转换可追溯；计量可覆盖生成和向量的全部 attempt；计时和数量口径可校验。人工审核未完成时运行必须标 diagnostic，不发布正式通过结论。

## B：完整原版记忆基线与恢复能力

交付：策略接口、带作用域的存储、原版写入/检索/反思适配器、快照和原子写入日志。

- 同一会话按每个实际参与者视角生成原版摘要，执行原版 importance 和 embedding，记录来源消息。保留原版反思条件与候选 10n、三项归一化、Top-K、访问节流。
- importance 解析失败的原版 fallback 等行为保持可识别并计数，不悄悄改成优化；必要公共修复对所有组一致应用并固定补丁。
- 世界、角色、实验/运行数据空间必须在检索前过滤。现有单世界数据保留；先备份，使用独立研究数据空间测试，不能把新增多世界直接接到只有 playerId 的索引。
- 同一作用域事件重复提交幂等；同 ID 不同内容拒绝。记忆与向量关联原子提交；重试可产生多个付费 attempt，但不得重复发布记忆。
- 原始事件与派生记忆独立；快照包括来源、向量版本、访问时间和维护状态。恢复后继续运行与未中断执行的可验证状态一致。
- 离线问题是共同的只读质量探针，查询在快照副本执行；两组使用相同检索问题模板。探针查询与在线交谈查询的适配差异写入 manifest。
- 候选服务若使用精确余弦替代 Convex 向量检索，标为适配变化并验证候选一致性；不能只复制排序公式就宣称完全等价。

完成条件：用固定 fixture 对照当前上游的写入提示词、阈值、候选/排序和访问更新；隔离、重复写、并发冲突、恢复测试通过；所有维护请求都有用途与来源。全历史控制组继续只作诊断。

## C：预算检索的首个开发对照

交付：baseline 与 budgeted_retrieval 接入同一固定工作负载 runner，产生 memory-actions、calls、answers 和成本质量报告。

先运行一个小规模完整流程，再在开发集对照 8K、1024 记忆预算、默认 K=3。该预算是开发起点，不是预先认定的最佳值。

两组同一摘要/评分/向量写入版本、同一候选池、同一输出预算、同一问题、同一初始快照；预算组在排序后整条选择，原版不因 memory budget 缩减 Top-K。对比查询的副本隔离，读取触发的 touch 不能污染另一组。端到端实验各自重建写入历史；共享预建快照的实验单独标 retrieval-only，不能省略维护成本后称总成本更低。

报告至少拆分：写入/维护、查询、失败重试、生成输入/输出、embedding、耗时与存储。输出候选证据是否召回、选中证据是否齐全、回答是否正确，分别定位 embedding、预算和模型错误。

完成条件：相同已完成事件/查询数量，150 个预期回答不遗漏失败；预算与完整模板不溢出；逐 attempt 对账。若预算不生效，报告“该条件下无变化”；若质量损失超过门槛，保留失败并定位，不能直接增加摘要掩盖原因。

## D：分层记忆与事实生命周期

交付：tiered_memory、版本化事实/承诺、归档查询、结构化输出校验与维护成本报告。

近期情节先保留原记录；有效事实携带人物/属性、有效时间和原始来源；承诺携带接受者、截止时间及完成证据；归档保存被替换/过期版本。检索当前状态与检索历史状态使用不同时间过滤。无法确定是替代还是并存时保留两条并标冲突，不凭文本相似就覆盖。

先按作用域和原始事件 ID 去重，禁止跨日期按相同文本任意删除。生成式抽取只接受合法结构和当前角色可见的来源；未知来源、循环来源或非法 JSON 不提交事实。较高 importance/confidence 不等于证据更正确。

维护触发按新增事件数或活跃 token 阈值冻结，避免每个 tick 摘要。触发值先在开发集选定，再冻结并计入配置；增量更新和全量重建作为不同消融。先测未压缩事实分层，再测生成式摘要，区分哪一步贡献收益。

完成条件：更新前后与历史查询正确；否定、关系、到期承诺不丢失；角色隔离、幂等、来源、恢复通过；非法模型输出不制造默认事实。所有维护开销入账，并可回答是否随查询次数增长而回本。

## E：完整离线矩阵与质量门槛

8K：两种历史总量 100/1000、50 问、每配置 3 次；baseline 各历史只跑一个原版配置，两个优化组各扫 512/1024/2048/4096。完整计划共 18 个配置、2700 个查询回答，另外预算写入/评分/反思/embedding 调用；不能沿用仅支持 150 查询的额度。重建每组历史和请求额度前先根据实测维护次数估算运行规模，单 run 不足则明确失败或预先分批，不中途无记录扩额。

先做 C 的小开发对照，再按此矩阵推进，不在 baseline 尚未验证时启动全部扫描。每角色 100/1000 可见事件作为额外容量扩展，用独立 dataset ID；不替换或混称既有全镇 100/1000 矩阵。

质量门槛继续使用已约定值：事实召回相对 baseline 下降 ≤5 个百分点，矛盾率上升 ≤2 个百分点，承诺完成率下降 ≤5 个百分点。现有问答只可评估承诺理解；补充有接受、到期、执行与证据事件的任务 runner 后才计算完成率。没有该指标时质量门槛是部分验收，不能称全部达标。

报告每类、每次重复、平均与范围，并列出未完成样本。150 次回答对应 50 个独立问题的重复，不视为 150 个独立问题；后续置信度分析按问题/场景分组。矛盾与无答案幻觉不能都简单等同于所有错误答案。

选择规则：先过全部质量门槛，再按 ROADMAP 比较总生成模型 token。这里明确定义为生成模型的 input + output tokens，包含维护与重试；输入和输出仍分项，embedding 单列。该总量只是固定模型下的计数指标，不是能耗或金钱。未知 usage 存在时只给覆盖率与下界，不能据不完整总量排名。成本多项方向不一致时报告权衡，不能只看输入宣布总消耗下降。

完成条件：有可追溯矩阵、全部质量指标、冻结数据/版本、每配置重复分布；无合格方案同样输出结果，不事后改门槛。

## F：4K、在线与复现

选出合格开发配置后，4K 扫描 512/1024/2048。共用输出预留与完整模板安全约束；4096 记忆预算不进入 4K。基线不可执行时不计算以其为分母的节省率，只报告可行性与质量。

完成 P4 后，按 P5 执行 baseline 与选中方案各 3 次×2 小时，补充超时、服务关闭、无效输出、重启和额度耗尽恢复。在线轨迹可能不同，比较每任务/每互动成本及活动量，并披露轨迹变化。最后 P6 在干净独立数据目录重建代表性配置，保留所有失败和已知限制。

# 实验规范

## 模型预验证与两层实验

先用 20 道开发题和 50 道冻结验收题验证模型。验收题每类 10 道，直接提供最小必要证据，重复 3 次；整体正确率 ≥90%，每类 ≥80%。开发题用于调试；标准答案与来源须人工复核。必要证据组是诊断组，不向正常 Agent 提供评估答案。

8K 是主窗口，4K 是压力测试。外部历史可以超过窗口；只有选中的记忆进入当前提示词。模型窗口与 memory budget 是两个独立变量。

算法实验使用 100/1000 条事件历史、固定 50 个查询；8K 下扫描 512/1024/2048/4096 的记忆预算，每配置至少 3 次。4K 下使用 512/1024/2048 预算。完整基线放不下时标记不可执行，不能静默截断。

**固定工作负载（优先）**：固定每个角色的观察序列、查询、承诺和任务，给不同记忆策略相同输入。比较输入 token、总成本和答案质量。

**在线小镇（后续）**：使用相同初始场景，观察行为反馈和长期运行。模型输出会改变后续轨迹，不能把不同轨迹当作完全相同的工作负载；报告互动数、事件数及轨迹差异。

当前 `configs/experiment.example.json` 仍是草案，`index.js` 只检查关键字段。已有模型摘要、诊断数据和 full_history_control 执行器，但完整策略执行器未接入；`UNSET` 未替换前不能开展正式实验。详细实施顺序见 [优化计划](OPTIMIZATION_PLAN.md)。

现已实现本地多查询开发 runner：每次重复重建会话记忆及维护，检索组从相同快照副本只读查询；这些写入/维护成本由各组共享并单独记账，比较口径为 retrieval-only。不能将维护总额无记录分摊成各组独立端到端成本。完整端到端对照仍需各组独立重建。相同问题的策略顺序跨重复反向轮换；报告实际顺序及种子，不把 KV 缓存命中造成的耗时变化归因于策略。

真实归档开发数据通过参与者/作者映射转换，不根据答案构造观察。Convex 的会话开始时间使用 archivedConversations.created，归档写入时间为 _creationTime，两者分开保存；小数毫秒向下取整进入 v2，原值保留在来源表。归档 numMessages 是引擎已处理计数，不必等于持久化消息行数；严格模式排除不一致会话，开发显式模式保留额外持久化行并逐条标注，不允许缺行伪装完整。两个相同读数不是数据库原子快照，遗留操作标记也不代表所有待处理任务已验收完成。

现有 100/1000 条是全镇观察总量，5 个角色各有 20/200 条；观察数不等于摘要写入后的 memory 数。报告同时列每角色可见历史、会话数和记忆数。当前承诺题测试理解；履行率需另接入实际任务和完成证据。

## 实验流程

1. 固定代码、容器、模型、参数和初始状态；计算校验和。
2. 建立评估集，覆盖事实、时间变化、人物关系、承诺、无答案问题与矛盾更新。人工确认标准答案及来源。
3. 预先确定质量门槛和停止条件，不根据结果事后放宽。
4. 先进行预热；冷启动和稳态分开报告，记录模型重载次数。
5. 在隔离世界/数据目录中运行各组；随机或轮换组顺序，减少温度、后台负载和缓存偏差。
6. 探索阶段每组至少 3 次，正式结论根据方差与效应量增加样本；固定 seed 不保证完全确定性。
7. 保存失败运行；只允许依据预先规定的基础设施故障规则剔除，并报告数量与理由。
8. 报告质量门槛是否满足，再讨论成本下降。不能只报告表现最好的单次运行。

## 指标口径

| 类别 | 指标 | 口径 |
| --- | --- | --- |
| 上下文 | input_tokens、retrieved_memory_tokens | 输入总量与其中记忆部分分开 |
| 生成 | output_tokens | 包括对话、摘要、评分、反思及可获得的推理 token |
| 向量 | embedding_calls、embedding_input_tokens | 单独报告，不按生成 token 假设等成本 |
| 请求 | logical_calls、attempts、failures | 一个逻辑请求可有多个计费/计算 attempt |
| 时间 | queue_ms、inference_ms、end_to_end_ms | 报告中位数、P95 及样本数 |
| 存储 | active_memories、archived_memories、bytes | 不只统计记录数 |
| 资源 | process_rss、docker_memory、memory_pressure | 记录采样方法和间隔；不同口径不直接相加 |
| 质量 | fact_recall、contradiction_rate、commitment_completion | 基于固定评估集、标准答案与观察资格 |
| 活动 | completed_tasks、interactions、processed_events | 避免少做工作造成虚假节省 |

输入节省率：`1 - variant_input_tokens / baseline_input_tokens`，只对相同工作负载计算；分母为 0 时记为不适用。

总生成 token 包括所有维护调用和失败重试中可获得的 usage。若有未知 usage，记录覆盖率和下界，不能把未知当零。生成、embedding、延迟与能耗是不同量纲，报告时保留分项，不随意加成一个“总成本分数”。

配置选择中的总生成模型 token 为 input_tokens + output_tokens，包含维护和重试；不与 embedding token 相加。输入、输出仍分别报告，且未知 usage 的下界不能当完整值排名。重复 3 次的 50 问对应 50 个问题，统计时不把重复回答视为独立新问题。

## 质量评估

- 事实召回：有资格知晓的标准事实中，正确回答比例；无答案题单独测幻觉率。
- 矛盾率：根据人物、时间和有效范围检查回答与证据是否矛盾。
- 承诺完成：角色已明确接受且在实验窗口内到期的承诺，实际完成比例。
- 当前 commitment-actions 工具可在固定已接受承诺与预建记忆快照上执行一次投递或等待，完成依据为受限执行器产生的状态变化/事件、对象/物品匹配及截止时间。目标注册表不传给模型；不得将该单步合成模拟器推广为在线自主接受、取消、重规划或长时任务完成。
- 事实更新：新证据到来后是否用新状态回答，同时能正确回答历史状态。
- 模型评审只能作为辅助，记录评审模型与盲评流程，并抽样人工复核。
- 固定质量探针只在快照副本或只读查询中执行，不能改变原运行记忆。

配置中的质量门槛单位为**百分点**。例如召回从 80% 到 76% 是下降 4 个百分点；不是下降 4%。

开发矛盾评估允许答案文件列 contradictionAnswers。仅匹配预先标注反答案时确认矛盾；正确回答或显式未知不计矛盾，其余未识别/非法/缺失输出不确定并报告未评覆盖。确认数/已评数与确认数/全部标注预期数的下界分开；不能用下界或弃答后的零矛盾选优。原文最小证据探针可诊断上下文表达失败，但定向选取证据不属于实际检索策略。

## 停止与异常

固定工作负载以完成固定输入为正常结束。达到墙钟上限、调用上限或资源阈值记为 `budget_exhausted` / `timeout`，不能与完整运行直接按总量比较。

初始防失控上限为每次运行 1000 次模型 attempt、1800 秒，配置草案中的 `maxTotalCalls` 按 attempt 计，含生成和 embedding。正式 runner 必须实际执行这些限制；目前检查工具不会执行。

在线模式另需指定事件/任务目标或模拟时长；自动空闲暂停必须关闭或记录。模型超时不把时钟停止造成的少事件计为优化收益。

## 结果文件

每次运行独立目录，至少包含：`manifest.json`、`config.json`、`events.jsonl`、`calls.jsonl`、`memory-actions.jsonl`、`resource-samples.jsonl`、`evaluation.json`、`summary.json`。

manifest 记录 run ID、variant、开始/结束时间、状态、停止原因、版本、数据校验和、硬件和计量覆盖率。原始结果目录不可被下一次运行覆盖；分析派生文件保留脚本版本。详细保留约定见 [experiments/README.md](../experiments/README.md)。
